# V1 — Full Scope, Staged Honestly

**Status:** Proposed (rev 3) · **Date:** 2026-07-29 (rev 2: 2026-07-27) · Companion to `DESIGN.md`, `WORKFLOW.md`, `CAPABILITIES.md`

**Operator ruling (2026-07-27):** nothing is out of scope. V1 = the full system — full work
management (no flat queue), full TMS, the learning/library layer, mobile view including reading
project docs on the phone, and **fully monitored** quota (not pause-on-limit). Decision 44 is the
mechanism that makes this honest: **every surface exists from day one; anything not yet functional
shows an explicit `blocked` state** and comes alive in a fixed order — never a fake, never a
stand-in that changes later.

**Realism up front (the three constraints no design removes):**
1. **Build capacity = quota.** The fleet building v1 draws the same Claude/Gemini windows the
   product manages. Calendar time is bounded by quota + integration risk, not ambition.
2. **The operator is the merge gate** (decision 45). Progress lands at review pace; full scope is
   a sustained multi-month program, not a sprint.
3. **Quota is read, not estimated** (decision 49). The operator can see real numbers on every
   service, so Podium reads the same authenticated own-account surfaces: Claude — `/usage`
   (PTY-parse) and the OAuth usage endpoint behind it; Gemini — `/stats` + exact client-side
   request/day + RPM counters; Codex (when added) — `/status` + app-server rate-limit methods.
   The metering ledger remains for attribution/history and reconciles against the read numbers;
   if a surface breaks the gauge shows **`unavailable`** (never a fake number, decision 44).

Estimates below are ranges with real uncertainty (greenfield, single reviewer, dogfooding
compounding both ways: acceleration once the loop works, drag while it doesn't).

---

## 1. The spine (unchanged): the loop that builds the rest

*You add a task → daemon runs it on Claude or Gemini in an isolated worktree → you watch live at
full terminal fidelity and can take over → it commits on a task branch → you approve / reject with
feedback → next task.* Every later stage of v1 lands **through** this loop as reviewed tasks.

## 3. Stage gates (order is dependency, not preference)

- **Stage A — the loop lives** (~2–4 weeks): spine + full work schema + TUI cockpit + metering
  ledger/gauge + takeover. *Gate: the bootstrap test — v1 executes a task from its own backlog.*
- **Stage B — connected + visible everywhere** (~3–5 weeks): interaction layer, ingestion, library
  reading + TTS, GitHub/Linear TMS, PWA read/monitor via tunnel, seeded model matrix, pacing
  controller. *Gate: you review a diff and read project docs from your phone; quota gauge drives
  admit/defer.*
- **Stage C — intelligent + autonomous** (~4–8 weeks): context engine via MCP, memory/guidelines,
  verifier gating `done`, autopilot over the DAG, always-on coordinator + offline cache, Jira,
  approval-inbox detectors, self-maintenance agents, **peer-call broker + subagent tree pane
  (decision 50)**. *Gate: an unattended evening run completes DAG-ordered tasks, verified, within
  quota pacing.*
- **Stage D — learning + full autonomy** (~4+ weeks, data-dependent): bandit routing live, learning
  paths + learner ML unlock **(estimates appearing in the decision-51 transparency pane, with
  evidence and edit/pin/reset)**, teams/handoff polish, runtime maintainer, auto-merge proposals.
  *Gate: rework-rate trend measurable; a low-risk auto-merge proposal correctly raised (you tap).*

Honest total: **~3–5 months of calendar time** at sustained dogfooding + your review pace, with
Stage A usable in weeks and every later stage adding capability *without ever changing shipped
semantics* (decision 44). Estimates carry wide error bars; the metering ledger itself will tell us
our real velocity within the first weeks — and that measurement, not optimism, re-plans the rest.

## 4. Definition of done (v1 = all stages)

All of rev-1's criteria (loop, visibility invariant, takeover, restart-resume, bootstrap test),
plus: full hierarchy + cross-project DAG scheduling live; GitHub + Linear + Jira sync running;
library reading + audio on the phone with laptop off; quota gauge continuously live (Claude
estimated + calibrated, Gemini exact) with admit/defer pacing demonstrated across a full week;
verifier gating `done`; seeded matrix routing with learning enabled; peer calls brokered-and-metered
with the subagent tree live and direct cross-harness calls still policy-denied (decision 50); the
operator-model pane showing every estimate with evidence and override (decision 51); zero surfaces
faked — every remaining `blocked` label corresponds to a real registered future increment.
